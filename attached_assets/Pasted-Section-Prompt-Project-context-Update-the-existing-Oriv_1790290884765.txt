Section,Prompt
Project context,"Update the existing Orivis application. Add persistent database storage for community reports while preserving the current reporting workflow, AI-generated analysis, user roles, dashboards, and simulated features."
Database,"Add and connect a Replit database. Create a community_reports table or equivalent database collection. The database must persist records after the app is refreshed or restarted."
Main action,"The main action is submitting a community safety report. Every time a Citizen or Parent submits a report, save the report and its AI-generated analysis to the database."
Report input fields,"Store the reporter account or family account ID, uploaded photo reference or filename, short description, selected issue category, dropped map-pin latitude, dropped map-pin longitude, and submission timestamp."
Supported categories,"Support blight, illegal dumping, unsafe bus stops, damaged sidewalks, poor lighting, suspicious activity, and other concerns."
AI output fields,"Store the simulated AI output, including generated issue category, short summary, severity score, recommended department, recommended priority, and confidence or review status if available."
Case management fields,"Also store the report ID, current case status, assigned city team, route assignment, manager notes, last updated timestamp, and resolved timestamp when applicable."
Initial status,"Every newly saved report should begin with the status Submitted. Allow authorized City Case Managers and City Workers to update status according to their existing permissions."
Second page,"Create a separate Report History or Saved Reports page that displays all saved community reports from the database. The page must show the original report input and the AI-generated output together."
Report list display,"For each saved report, show the report ID, photo or photo placeholder, description, issue category, location, severity score, current status, assigned team, and submission timestamp."
Sorting,"Display saved reports newest first using the submission timestamp. Do not use only temporary frontend state; load the records from the database whenever the page opens or refreshes."
Report details,"Allow a user to select a saved report and view its complete details, including the uploaded photo, map location, AI analysis, severity, status history if available, assigned team, and timestamps."
Permissions,"Citizens and Parents can view their own submitted reports. City Case Managers can view and edit all reports. City Workers can view assigned reports and update only their permitted status fields."
Database error handling,"Show a clear error message if a report cannot be saved or loaded. Do not falsely display a success message unless the database write succeeds."
Demo data,"Keep the existing sample reports and Reset Demonstration Data feature. Resetting demonstration data should restore the initial sample community reports and their AI outputs in the database."
Validation,"Require a short description, issue category or AI-generated category, and a valid location before saving. Allow a photo to be optional for the prototype, but save a placeholder value when no photo is provided."
Replit implementation instruction,"Implement the database schema, save operation, database read operation, newest-first sorting, report history page, report detail view, role-based permissions, error handling, and reset-demo behavior. Test that submitting a report creates a database record and that the record appears on the second page after refreshing the app."
